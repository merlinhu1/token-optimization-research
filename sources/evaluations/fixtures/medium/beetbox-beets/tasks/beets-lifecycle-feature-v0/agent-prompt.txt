Implement incremental multi-value `beet modify` assignments using the prescribed solution below. This is a controlled token-usage workload: follow the recipe directly rather than redesigning the command.

`field+=value` appends unique parsed values in order, `field-=value` removes exact parsed values, and ordinary replacement remains unchanged. Incremental operators on scalar fields must raise `UserError` before any object is modified.

## Implementation recipe

1. Work primarily in `beets/ui/commands/modify.py`.
2. Introduce a small typed immutable `ModifyOperation` carrying `operator` (`None`, `"+"`, or `"-"`) and the raw value string.
3. In argument parsing, split once on `=`, detect a trailing `+` or `-` on the field name, remove that suffix, then apply `maybe_replace_legacy_field` exactly as ordinary assignments do.
4. Before querying or mutating objects, validate every incremental operation with `model_cls._type(field).model_type is list`; raise `UserError` naming the field and operator for scalar fields.
5. Evaluate the existing value template for each object and parse it with the model's existing `_parse` method.
6. For `+`, copy the existing list and append parsed values not already present. For `-`, return existing values not exactly present in the parsed removal list. For `None`, return the ordinary parsed replacement.
7. Preserve confirmation by retaining each object's already prepared modifications rather than reusing raw operation objects.
8. Update only focused normal tests in `test/ui/commands/test_modify.py` if useful. Do not alter album, write, move, alias, or template semantics.
