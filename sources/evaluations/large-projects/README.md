# Large-project Evaluation Runs

Primary objective experiments live here.

The active first-wave fixtures are:

- `django-django` using `django/django`
- `hashicorp-terraform` using `hashicorp/terraform`

Round-one execution order and preflight gates live in `round-1-runbook.md`.

Use one subdirectory per target project:

```text
sources/evaluations/large-projects/<project-id>/
  README.md
  repo/                         # generated by task setup; do not commit
  tasks/<task-id>/task.md
  tasks/<task-id>/agent-prompt.txt
```

Rules:

- Keep baselines, individual-tool treatments, and stack treatments in the same `experiment_group_id`.
- Baseline runs must use the baseline tool manifest and must not expose any retrieval, compression, memory, MCP, or token-saving treatment tool.
- Codex-based reproduction runs must use the container backend in `scripts/run_codex_fixture_evaluation.py`; host execution is a diagnostic escape hatch only and is not container-grade evidence.
- Use `--build-docker-image` to build `token-eval-codex:latest` from `sources/evaluations/large-projects/container/Dockerfile` before preflight when the image is not already present.
- When Hermes itself runs in Docker with `/var/run/docker.sock` mounted, bind-mount sources are resolved on the Docker host. The runner translates `/opt/data/...` mount sources at runtime and redacts the actual host path from publishable artifacts, unless a private diagnostic record explicitly opts in.
- Container preflight artifacts are required before accepting a run: `container-preflight.json`, `docker-smoke-output.txt`, lane-specific `CODEX_HOME`, Codex preflight, event stream, verifier output, final diff/status, and isolation audit.
- Treatment runs must use the exact matching treatment manifest.
- Primary treatment runs normally use `tool_state = cold` and `tool_use_policy = optional`: no prebuilt tool state, and the agent may choose whether the active tool is worth using.
- Warm-state optional variants are calibration records, not default full-suite lanes. Mark them with `evaluation_protocol.calibration_only = true`; `scripts/run_codex_evaluation_batch.py` skips them unless `--include-calibration` is passed, and `--calibration-limit-per-profile` caps sentinel runs.
- Warmup/index commands are recorded as wall-time/output artifacts and are not counted as provider tokens unless their output appears in `codex-events.jsonl`.
- Run `scripts/audit_tool_isolation.py` on the Codex event stream plus preflight artifacts before accepting a run.
- Append completed, failed, excluded, and negative records to `data/evaluations.json`; do not overwrite them.
- Small generated fixtures belong to calibration and diagnostic checks, not primary objective claims.
