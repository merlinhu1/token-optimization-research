# Evaluations

The production evaluation surface is lifecycle v0 only. Three pinned fixtures—Fastify, Beets, and Terraform—each exercise feature implementation, behavior-preserving refactor, and code review/correction in one persistent workflow.

Each lane has two retained operationally valid baseline replicates (`r0` and `r1`) in `data/workflow-sessions.json`, with compact evidence under `sources/evaluations/workflow-sessions/`. Verifier and optional source-review outcomes are diagnostic; complete provider usage and execution integrity determine token-accounting eligibility.

Fourteen natural-use treatment screens are complete: Caveman, RTK, Serena, Ponytail, Token Savior, Graphify, CodeGraph, jcodemunch MCP, SigMap, LeanCTX, Snip, TokenJuice, Headroom, and Cartog each produced three compatible `r1` paired comparisons. The newest aggregate provider-token changes were Snip -19.16%, TokenJuice -28.54%, default Headroom -3.24%, and Cartog -18.62%. Headroom's required proxy-only companion ablation used 5.47% more tokens than the matched baseline and is not ranked as a separate full-tool screen. All 15 newest sessions are operationally valid and token-accounting eligible; the four primary screens passed 33/36 verifier tasks and the ablation passed 8/9, with those outcomes retained as separate diagnostics. These are first valid assignment-level samples under each product's frozen integration. Explicit model-issued command counts are not treated as universal mechanism-activity measures, and no forced invocation is permitted. Treat every result as an initial single-replicate screen rather than a stable estimate. Start with `workflow-evaluation-runbook.md`, then use `token-usage-and-quality-standards.md` and `cumulative-result-schema.md` for preregistered natural-use replication.
