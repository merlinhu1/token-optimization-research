# Evaluations

The production evaluation surface is lifecycle v0 only. Three pinned fixtures—Fastify, Beets, and Terraform—each exercise feature implementation, behavior-preserving refactor, and code review/correction in one persistent workflow.

Each lane has two retained operationally valid baseline replicates (`r0` and `r1`) in `data/workflow-sessions.json`, with compact evidence under `sources/evaluations/workflow-sessions/`. Verifier and optional source-review outcomes are diagnostic; complete provider usage and execution integrity determine token-accounting eligibility.

Ten natural-use treatment screens are complete: Caveman, RTK, Serena, Ponytail, Token Savior, Graphify, CodeGraph, jcodemunch MCP, SigMap, and LeanCTX each produced three compatible `r1` paired comparisons. Their matched aggregate provider-token changes were -14.05%, -12.72%, -3.27%, -1.21%, -14.89%, -16.38%, -17.15%, -17.58%, +11.69%, and -5.12%, respectively. Every session is operationally valid and token-accounting eligible; verifier outcomes remain separate diagnostics. These are first valid assignment-level samples under each product's frozen integration. Explicit model-issued command counts are not treated as universal mechanism-activity measures, and no forced invocation is permitted. Treat every result as an initial single-replicate screen rather than a stable estimate. Start with `workflow-evaluation-runbook.md`, then use `token-usage-and-quality-standards.md` and `cumulative-result-schema.md` for preregistered natural-use replication.
