Why we ran this

AI coding agents are billed for every piece of text they read and write. A fast-growing set of optimizers promises to cut that bill, often by 20 to 60 percent. Most of those figures come from the makers, measured once. We measured each optimizer against the same agent doing the same real bug fixes without it, then repeated the runs that looked promising. No maker sponsored the study or saw the results in advance.

01 The noise

Run the same job twice, and the bill can move by 54.5%.

Before testing any optimizer, we ran each agent on the same six bug fixes several times with nothing installed. Same code, same instructions, same agent. The cost still moved.

How to read it

Each dot is one run, placed by how far its cost landed from the typical run. The band spans the cheapest to the most expensive run, and the figure on the right is the gap between them.

Why it matters

This swing is the bar every optimizer has to clear. A one-off comparison showing a 20% saving can sit entirely inside it. Each time we added another run, the swing widened or held steady. It never narrowed.

02 The second run

Four of five early wins didn't survive a second run.

We took the five single-run savings that cleared the noise by the thinnest margins and ran each one again. The hollow dot is what one test showed. The solid dot is the result after two.

How to read it

Each arrow runs from the first result to the result after two runs. Left of zero is cheaper. The shaded band is the normal swing for that agent and project; a dot inside it cannot be told apart from luck.

Why it matters

The size of a first-run saving said nothing about whether it would last. The one that held had the thinnest margin of the five. Treat any single comparison, a maker's included, as a lead rather than a result.

04 The mechanism

Real savings come from two different places.

An agent's bill is the number of steps it takes multiplied by the cost of each step. For every proven saving, this shows which of the two moved.

How to read it

Further left, the agent took fewer steps. Further down, each step was cheaper. The curved lines join points with the same total saving: 0%, 25% and 50%.

Why it matters

A fewer-steps optimizer changes how the agent works through a problem. A cheaper-steps optimizer trims what it reads. They solve different problems, so one may suit your codebase when the other does not.

So what

Before you buy an optimizer, ask three questions.

How many runs is the claim based on?

One before-and-after comparison can show a 20 to 50 percent "saving" by chance. Ask for repeated runs and the spread between them.

Was it measured on code like yours?

Every proven saving here came from one project. None carried over to the second. Run a trial on your own repository.

Was it measured with your agent?

The same optimizer lowered the bill with one agent and raised it with another. Test with the agent and model you actually use.

Fine print

What this study cannot tell you

  • Which optimizer is best. The proven savings sit closer together than the normal swing.
  • That unproven means useless. — of — setups were tested only once, which is not enough to decide either way.
  • Anything from run counts. Promising first results were re-tested, so more runs does not mean better.
  • Agent versus model. Claude Code runs Claude Opus 5; Codex CLI and OpenCode run GPT-5.6 Sol, so the two are tied together.
  • Quality. Cost was counted whether or not a fix was right. — of — fixes passed the project's own tests.

How we tested

  • Real work. Six genuine bugs per project, taken from each project's history and checked by its own tests.
  • Identical instructions. The agent is told the symptom only, never where to look and never to use the optimizer.
  • Fair installation. Each optimizer installed the way its maker recommends, tested on its own.
  • Frozen versions. Agent versions were pinned for the whole study.

Terms

AI coding agent
Software such as Claude Code, Codex CLI or OpenCode that reads a codebase and changes it on its own.
Optimizer
An add-on that promises to lower what the agent is billed for.
Token cost
new text + 0.1 × re-read text + 6 × written text, mirroring how AI providers price usage.
Proven saving
Tested at least twice and cheaper by more than the normal swing with no optimizer.
